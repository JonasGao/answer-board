# 题内引用：questions[].refs 承载被引条目原文

round JSON 的 `questions[].refs` 是可选字符串数组，放本题引用的源文档条目原文：body 提到「新增 ①」「第 3 条」这类编号引用时，被引内容渲染在题干下方、选项之前，按纯文本处理。跨题共享的引用仍走顶层 `facts`；一句话能说清的可内联进 body。字段只影响展示，不进答案、不影响提交校验。

动因是 2026-11-18 OMC 需求面板 round 1 Q3：题干写「整合后新增 ① 之前半」，① 指向需求文档第十节第 3 条，但左侧 facts 没有该条原文。作答者不知道 ① 是什么，未作答并在补充说明里反问，round 2 改直白问法才拿到答案，多耗一整轮投递。全局 facts 解决不了单题引用：要么撑爆参考栏，要么把无关条目塞给其他题。

关键取舍：纯文本数组，不引入结构化 `{label, text}`——编号标签（①、第 3 条）本就写在被引原文里，作者照抄即可，结构化只是多一层易错字段；沿用 facts/defaults 的纯文本约定，`body` 仍保持唯一 Markdown 字段。渲染位置在题干与选项之间而非题尾：读者在 body 里撞到编号引用时，原文就在下一段视线内。被否方案：自动编号脚注（与源文档自身编号冲突）、refs 走 Markdown（扩大渲染面，引用原文通常无需富文本）、服务端校验 refs 形状（延续「脚本不校验、写错看得见」哲学，形状写错页面 500 可见）。

以上取舍由维护者于 2026-11-18 基于 OMC 面板反馈定案。
